# AI 티 체크리스트

> **상태: 조사 자료 (검토 전).** 여백 DS 규칙이 아니다. 반영 여부는 [`review.md`](review.md) 에서 정한다.
> 점검할 때 참고 체크리스트로는 써도 된다.

AI로 만든 화면이 "AI가 만든 것 같다"는 인상을 주는 자리와, 지우는 방법 후보.

> 핵심: AI 티는 AI를 써서 나는 게 아니라 **아무도 정하지 않은 기본값이 남아서** 난다.
> 신호 하나로는 괜찮다. **손대지 않은 기본값이 서너 개 겹칠 때** 티가 난다.

조사일: 2026-11-27 · 다음 갱신: 주간 리서치에서 새 신호가 나오면 이 파일에 더한다.

---

## 1. 화면(시각) 신호

| # | 신호 | 왜 티가 나나 | 여백식 처방 |
|---|---|---|---|
| V1 | 보라→파랑 그라디언트, 비슷한 강조색 여러 개 | 브랜드 색을 아무도 안 정했다는 표시 | 중립색 + 강조색(파랑) 하나. 파랑은 누를 수 있는 것에만 |
| V2 | 제목·본문·캡션 전부 같은 산세리프 한 벌 | 위계와 성격이 없음 | 제목용 굵기·자간을 본문과 확실히 다르게. 필요하면 제목 서체를 따로 |
| V3 | 모든 요소에 같은 큰 둥근 모서리 | 역할 구분이 안 됨 | `--radius-sm/md/lg` 를 역할별로만 (태그·인풋 / 버튼 / 카드) |
| V4 | 모든 카드에 같은 옅은 그림자 | 떠 있을 이유 없는 것까지 띄움 | 그림자는 모달·드롭다운처럼 실제로 뜨는 것에만. 카드는 테두리나 배경 차이로 |
| V5 | 간격이 전부 같음 | 묶음이 안 보임 | 묶음 사이 여백 > 묶음 안쪽 여백. 차이를 확실히 |
| V6 | 제목·부제·본문까지 가운데 정렬 | 템플릿 첫 화면 그대로 | 가운데 정렬은 두 줄 이하 짧은 글에만. 본문은 왼쪽 |
| V7 | 같은 크기 카드 3장(또는 9장) 격자 | 위계 없음, 뭐가 중요한지 모름 | 한 화면 한 가지 일 — 주인공 하나를 크게, 나머지는 조용히 |
| V8 | 섹션 제목·목록마다 이모지 | 장식용 이모지 | 상태 구분이 필요한 곳에만. 나머지는 굵기·색 신호로 |
| V9 | 3D 블롭, 유리 질감, 스톡 일러스트 | 실제로 보여줄 게 없다는 표시 | 실제 화면 캡처, 실제(또는 예시라고 밝힌) 데이터, 도표. 없으면 비워 둔다 |
| V10 | 이유 없는 스크롤 페이드·떠오르기 | 반응하지 않는 장식 모션 | 모션은 누른 것에 대한 피드백이나 시선 유도에만 |
| V11 | 어두운 배경 + 발광(glow), 색 있는 버튼 그림자 | 바이브 코딩 사이트의 흔한 조합 | 그림자는 검정 계열 토큰만. 색 그림자 금지 |

## 2. 문구 신호

| # | 신호 | 예 | 처방 |
|---|---|---|---|
| C1 | 어느 회사에나 붙는 헤드라인 | "혁신으로 비즈니스를 성장시키세요" | 손님·문제·결과를 이름으로 말한다 |
| C2 | "A가 아니라 B" 대구, 같은 길이 문장 셋 | "~가 아니라 ~입니다." | 길이가 다른 문장을 섞는다. 형용사보다 구체 명사 |
| C3 | 셋씩 묶는 나열이 반복됨 | "빠르고, 쉽고, 안전하게" | 실제 개수대로 쓴다. 둘이면 둘 |
| C4 | 대시(—) 남발 | 제목마다 "A — B" | 한 화면에 한두 번. 나머지는 마침표·쉼표 |
| C5 | 같은 슬로건 여러 번 반복 | 히어로·소개·마무리에 같은 문장 | 한 번만. 마무리는 행동(문의·써 보기)으로 끝낸다 |
| C6 | 과장 형용사, 입장 없는 혜택 나열 | "최고의", "강력한", "다양한" | 숫자·조건·한계를 쓴다. 하지 않는 일을 밝힌다 |
| C7 | 부정으로 안심시키기 반복 | "~도 ~도 없어요" 연속 | 한 번이면 충분. 나머지는 할 수 있는 것으로 |

## 3. 증거·신뢰 신호 (가장 크게 깎이는 곳)

| # | 신호 | 처방 |
|---|---|---|
| T1 | 만든 사람이 안 보임 | 이름(또는 활동명), 하는 일, 경력, 연락 수단을 한 곳에 |
| T2 | 실제 화면이 없음, 설명만 있음 | 홈 첫 화면에 실제 결과물 캡처 하나 |
| T3 | 언제 갱신됐는지 모름 | 항목마다 날짜("11월 20일 추가"). "새 것" 라벨보다 날짜 |
| T4 | 출처·조건·한계가 없음 | 숫자 옆에 출처·기준일·처리 방식. 불리한 점도 먼저 말한다 |
| T5 | 페이지마다 메뉴·구성이 다름 | 같은 상단 메뉴, 같은 푸터. 페이지를 따로 생성했을 때 흔한 흔적 |
| T6 | 푸터에 소개·문의·개인정보처리방침이 없음 | 기본 세트를 갖춘다 |

## 4. 코드·메타 신호

- 템플릿 그대로의 meta description, 기본 OG 이미지, "image" 같은 alt
- 안 쓰는 클래스, 반복 구조, 접근성 누락 → `a11y_check.py` 로 대비 점검, 키보드 포커스 확인

## 6. 사람들이 편해하는 화면의 공통점 (닐슨 노먼 그룹 홈페이지 지침 요약)

1. 첫 문장 하나로 무엇을 하는 곳인지 말한다
2. 손님이 하러 온 일 1~4개로 바로 가는 입구가 있다
3. 회사·운영자 정보는 한 곳에 모은다
4. 설명보다 **실제 콘텐츠의 구체적 예**를 보여준다
5. 링크 글자는 가장 중요한 단어로 시작한다
6. 최근 항목 몇 개 + 지난 것 모음
7. 내비게이션 같은 중요한 곳에 장식을 덜어낸다 (광고로 오인)
8. 실제 사람 사진, 주제와 관련된 이미지를 쓴다

## 7. 검증하는 법

- **5초 테스트**: 처음 보는 사람 3~5명에게 첫 화면을 5초 보여주고 "무슨 곳 같아? 누가 만든 것 같아?"를 묻는다
- 첫인상은 0.05초 안에 생기고 오래 유지된다는 연구(Lindgaard 외)가 있어서 첫 화면이 가장 중요하다
- 위 표를 체크해서 걸린 개수를 센다. 화면 신호 3개 이상 겹치면 우선 수정
